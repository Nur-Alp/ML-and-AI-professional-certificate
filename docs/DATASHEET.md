# Datasheet: BBO Capstone Function Data

Following the spirit of [Datasheets for Datasets](https://arxiv.org/abs/1803.09010), scoped to this capstone's synthetic data.

## Motivation

The data was created by the course instructors for the Bayesian Black-Box
Optimisation (BBO) capstone challenge. Its purpose is pedagogical: to give
students a realistic experience of optimising an unknown, expensive-to-query
function under a tight evaluation budget, one query per function per week,
mirroring real scenarios such as drug formulation testing, manufacturing
parameter tuning or hyperparameter search where each evaluation is costly.

## Composition

The data consists of eight independent synthetic "black-box" functions,
each with a different input dimensionality:

| Function | Dimensions | Initial points | Real-world analogy |
|---|---|---|---|
| 1 | 2 | 10 | Radiation/contamination source detection |
| 2 | 2 | 10 | Noisy log-likelihood optimisation of a mystery model |
| 3 | 3 | 15 | Drug discovery (minimising adverse reactions, negated to a maximisation problem) |
| 4 | 4 | 30 | Warehouse product placement, approximated by a fast surrogate model |
| 5 | 4 | 20 | Chemical process yield (described as typically unimodal) |
| 6 | 5 | 20 | Recipe optimisation (multi-factor score, negated to maximisation) |
| 7 | 6 | 30 | ML hyperparameter tuning (accuracy/F1 as the objective) |
| 8 | 8 | 40 | ML hyperparameter tuning, higher-dimensional |

Each function's data is a pair of NumPy arrays: `initial_inputs.npy`
(shape `(n, d)`) and `initial_outputs.npy` (shape `(n,)`). All input values
lie in `[0.000000, 0.999999]`. Output values may be positive or negative;
several real-world analogies are naturally minimisation problems (fewer side
effects, lower cost) and have been transformed by negation so that, within
this project, higher is always better.

The dataset grows by one new (input, output) pair per function each week, as
the capstone portal processes each round's submitted query.

## Collection process

The initial points were provided directly by the course instructors as
`.npy` files. Subsequent points are generated by submitting a query (an
input vector) through the capstone portal; the portal evaluates the true
(hidden) function and returns the corresponding output, which is then
appended to the local dataset for use in the following round.

## Preprocessing

No preprocessing was applied. Inputs are already continuous and normalised
to `[0, 1)` by the challenge's own design; no scaling, encoding or cleaning
was necessary.

## Uses

This data is intended solely for developing and evaluating optimisation
strategies (Bayesian optimisation, in this project) within the capstone
challenge. It is synthetic and has no meaning or validity outside this
context.

## Limitations

- **Unknown ground truth:** the true functions and their global optima are
  never observed directly, only sampled points. Any conclusion about a
  function's shape (e.g. "unimodal") is based on the instructors' provided
  description, not independently verified.
- **Small sample sizes relative to dimensionality:** particularly for the
  higher-dimensional functions (Function 7 at 6D with 30-31 points, Function
  8 at 8D with 40-41 points), the available data is sparse relative to the
  input space, so any surrogate model's predictions carry substantial
  uncertainty, especially in regions far from existing samples.
- **Possible sparse/near-zero signal:** Function 1's observed outputs are
  almost entirely indistinguishable from zero in the data collected so far,
  consistent with its description as a proximity-only detection problem.
  This means a surrogate model has very little gradient information to work
  with until a genuinely informative (non-zero) point is found.
- **No independent noise characterisation:** the level and type of
  observation noise (if any) has not been independently measured; it is
  assumed small and is not treated specially by the modelling approach used
  here.

## Distribution and maintenance

This data is private coursework material for the capstone challenge and is
not intended for redistribution outside that context. The local copy in
`data/initial_data/` is updated by the student after each week's portal
submission is processed, by appending the new (input, output) pair to the
existing arrays.
