# Datasheet: BBO Capstone Function Data

Following the spirit of [Datasheets for Datasets](https://arxiv.org/abs/1803.09010), structured per capstone component 21.2, and scoped to this capstone's synthetic data.

## Motivation

This dataset was created to support the Bayesian Black-Box Optimisation (BBO)
capstone challenge: an unsupervised, query-driven exercise in optimising
eight unknown functions under a tight evaluation budget of one query per
function per week. Its purpose is pedagogical, to give hands-on experience
with the realistic constraint that defines most real-world optimisation
problems, evaluations are expensive, so every query has to be chosen using
everything learned from the queries before it. The real-world analogies
behind the eight functions (radiation source detection, drug discovery,
warehouse placement, chemical process yield, recipe optimisation, ML
hyperparameter tuning) all share that same expensive-evaluation structure.

## Composition

The dataset consists of eight independent synthetic "black-box" functions,
each with a different input dimensionality and its own real-world analogy:

| Function | Dimensions | Initial points | Points after round 9 | Real-world analogy |
|---|---|---|---|---|
| 1 | 2 | 10 | 19 | Radiation/contamination source detection |
| 2 | 2 | 10 | 19 | Noisy log-likelihood optimisation of a mystery model |
| 3 | 3 | 15 | 24 | Drug discovery (minimising adverse reactions, negated to maximisation) |
| 4 | 4 | 30 | 39 | Warehouse product placement, approximated by a fast surrogate model |
| 5 | 4 | 20 | 29 | Chemical process yield (described as typically unimodal) |
| 6 | 5 | 20 | 29 | Recipe optimisation (multi-factor score, negated to maximisation) |
| 7 | 6 | 30 | 39 | ML hyperparameter tuning (accuracy/F1 as the objective) |
| 8 | 8 | 40 | 49 | ML hyperparameter tuning, higher-dimensional |

Each function's data is a pair of NumPy arrays: `initial_inputs.npy`
(shape `(n, d)`) and `initial_outputs.npy` (shape `(n,)`), stored under
`data/initial_data/function_{1-8}/`. All input values lie in
`[0.000000, 0.999999]`. Output values may be positive or negative; several
real-world analogies are naturally minimisation problems and have been
transformed by negation so that, within this project, higher is always
better. There are no missing values within the collected data, the only
"gap" is structural, the true functions themselves are never observed
directly, only sampled points, so the dataset's coverage of each 2D-8D input
space is necessarily sparse, especially for the higher-dimensional
functions.

## Collection process

The initial points (10-40 per function) were provided directly by the
course instructors as `.npy` files. Every subsequent point was generated by
this project's own GP+UCB strategy (documented in
[MODEL_CARD.md](MODEL_CARD.md)): fit a Gaussian Process surrogate on all
data collected so far, maximise an Upper Confidence Bound acquisition
function over a large random-plus-local candidate pool, and submit the
resulting point through the capstone portal, which evaluates the true
hidden function and returns the corresponding output. That output is then
appended to the local dataset for use in the following round. Ten rounds
were collected this way, roughly one per week, from the point the pipeline
was first built through round 10's proposals.

## Preprocessing and uses

No preprocessing was applied to the raw data. Inputs are already continuous
and normalised to `[0, 1)` by the challenge's own design, so no scaling,
encoding or cleaning was necessary before feeding them to the GP surrogate.
The one transformation applied is at the acquisition-search stage rather
than the data itself: `propose_next_point` (added at round 10) excludes any
candidate query point within 0.02 of an already-observed point, after a
diagnostic pass found the raw UCB proposal for Function 5 was an exact
duplicate of an already-queried, confirmed-deterministic point.

This data is intended solely for developing and evaluating optimisation
strategies within the capstone challenge, and it is synthetic, with no
meaning or validity outside that context. Inappropriate uses include: using
it to train or benchmark models intended for deployment outside the
capstone, treating the real-world analogies as anything more than
illustrative framing, or drawing conclusions about a function's true global
optimum from the sparse, exploration-biased sample collected so far, since
the sampling strategy deliberately concentrates queries near already-good
regions rather than covering the input space uniformly.

## Distribution and maintenance

This data is coursework material for the capstone challenge, held in a
public GitHub repository
([Nur-Alp/ML-and-AI-professional-certificate](https://github.com/Nur-Alp/ML-and-AI-professional-certificate))
for transparency and peer review as required by the programme, but not
intended for reuse outside that context. The local copy in
`data/initial_data/` is maintained by the student, updated each week by
appending the new (input, output) pair returned by the portal to the
existing arrays, with every update committed to version control alongside a
description of what changed and why.

## Limitations

- **Unknown ground truth:** the true functions and their global optima are
  never observed directly. Any description of a function's shape (e.g.
  "unimodal") comes from the instructors' provided description, not
  independent verification.
- **Small sample sizes relative to dimensionality:** the higher-dimensional
  functions (Function 7 at 6D, Function 8 at 8D) remain sparse relative to
  their input space even after nine rounds, so surrogate predictions carry
  substantial uncertainty away from existing samples.
- **Exploration-biased sampling:** because queries are chosen to maximise an
  acquisition function rather than sampled uniformly, the dataset is denser
  near regions the model already believes are good, and correspondingly
  sparser elsewhere. This is a deliberate, useful bias for optimisation, but
  it means the dataset is not representative of the input space as a whole.
- **No independent noise characterisation:** the level and type of
  observation noise has not been independently measured. Function 5's
  rounds 6 and 7 returning an identical value for an identical query
  suggests at least that function is deterministic (or has negligible
  noise), but this hasn't been confirmed for the others.
